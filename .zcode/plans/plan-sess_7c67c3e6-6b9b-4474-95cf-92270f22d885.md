# 回答生成中「排队发送」功能实现计划

## 背景结论（已调研确认）

- 前端聊天逻辑全部在 `frontend/src/components/ChatWorkspace.tsx`（712 行单文件），当前 `send()` 在 `loading` 时直接 return 静默丢弃输入（387 行）；生成中发送按钮被替换为停止按钮（685-704 行三目互斥）。
- **后端无需改动**：客户端 abort 即真正停止 LLM 生成，部分回答由 `_save_partial`（shield + 独立 session）落库并标记 `stopped: true`；Agent 每轮无状态重建，取消后立即发新请求天然支持。
- 排队串行化由前端完成：当前流结束后自动按 FIFO 发送队首，避免后端两条流并发交错落库。

## 改动文件：仅 `frontend/src/components/ChatWorkspace.tsx`

### 1. 新增排队状态（含 ref 镜像，避免异步链路读到过期闭包）

```ts
type QueuedMessage = { id: string; content: string; attachments: string[] };

const [queue, setQueue] = useState<QueuedMessage[]>([]);
const queueRef = useRef<QueuedMessage[]>([]);            // 同步镜像
const busyRef = useRef(false);                            // 流式进行中（同步版 loading，控制流用）
const immediateNextRef = useRef<QueuedMessage | null>(null); // 「立即发送」插队项
const skipNextDrainRef = useRef(false);                   // 显式停止/出错后本轮不自动出队
const sendRef = useRef(send); sendRef.current = send;     // latest-ref：出队时用最新闭包（读到最新开关/会话 id）
const updateQueue = (next) => { queueRef.current = next; setQueue(next); };
```

### 2. 改造 `send()`

- 入口守卫：空内容仍拦截；**`busyRef.current === true` 时不再丢弃，而是把内容+附件 push 进队列**、清空输入框、`message.info('已加入发送队列')` 后 return（Enter 和发送按钮都自然走这条路）。
- 真正开始发送时：`busyRef.current = true`（与 `setLoading(true)` 并行），并清一次 `skipNextDrainRef` 防残留。
- `finally` 末尾：`busyRef.current = false` 后调用 `drainQueue()`。

### 3. 出队调度 `drainQueue()`（只读 ref，不读 state）

```
busy 中 → return
skipNextDrainRef 置位 → 消费掉并 return（停止/出错后不自动续发）
immediateNextRef 有值 → 取出并 sendRef.current(它)   ← 「立即发送」插队优先
否则队首出队 → updateQueue(rest) → sendRef.current(队首)  ← 轮候：当前回答结束后自动发送
```

### 4. 「立即发送」`sendNow(item)`

从队列移除该项；若当前空闲直接发；否则 `immediateNextRef.current = item` + `abortRef.current?.abort()` —— 旧流的 finally → drainQueue 会优先发它（旧回答按现有逻辑落库并标记「已停止生成」）。若 `immediateNextRef` 已被占用则忽略本次点击，防止连点丢消息。

### 5. 「停止生成」语义调整

`stopGenerating()`：置 `skipNextDrainRef = true` 再 abort —— **停止当前生成但保留队列不自动续发**，排队卡片仍可手动 立即发送/编辑/删除；用户手动再发新消息时插队先行，之后队列继续轮候。`catch` 的非 abort 错误分支同样置 skip（出错后不自动连环重试）。

### 6. 新增 `QueueCard` 组件（按图还原）

渲染在消息列表与输入框之间（`mx-auto max-w-[800px] mb-2 space-y-2`，与输入框同宽对齐），结构：

- 拖拽手柄 `HolderOutlined`（仅按住手柄时 `draggable`，HTML5 原生拖拽，dragEnter 实时换序）
- 序号徽标：圆角圆形底 `index + (loading ? 2 : 1)`（图中第一张排队卡显示「2」，在途提问算 1）
- 内容区：`line-clamp` 限高的 whitespace-pre-wrap 文本；附件复用 `AttachmentThumb` 缩略图
- 操作区：`立即发送`（小号胶囊按钮）+ 铅笔 `EditOutlined` + 垃圾桶 `DeleteOutlined`（danger text 按钮）
- 行内编辑模式：卡片内变 textarea + 取消/保存（Enter 保存、Esc 取消，风格同 UserMessage 编辑态）；附件不参与编辑
- 复用现有 `msg-in` 入场动画与 Tailwind 语义 token（`border-line bg-soft text-muted` 等），自动适配明暗主题

### 7. 输入区调整

- 占位符：生成中改为 `继续输入以排队后续修改`（按图），空闲时保持 `给 Friday 发送消息…`
- 生成中**同时显示**停止按钮（`ml-auto`）与发送按钮（描边次级圆形，非主色渐变，空内容禁用）——不再三目互斥

### 8. 会话切换清理

会话切换 `useEffect` 中追加：`updateQueue([])`、清空 `immediateNextRef`、置 `skipNextDrainRef`，防止在途流的 finally 把排队消息发进新会话。

### 9. 保持不变的行为

- 历史消息「编辑重发」仍生成中禁用（截断历史与流式互斥，危险操作）。
- `UserMessage`、权限卡片、打字机缓冲等逻辑不动。
