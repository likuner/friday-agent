# 工作区移入侧边栏 + 会话记住权限模式（含移动端）

## 后端改动

1. **models.py**：`ConversationSetting` 加 `permission_mode TEXT 可空` 列；`Conversation` 加一对一 relationship `setting`（`uselist=False`，级联删除），供列表/详情一次性带出。
2. **db.py `init_db()`**：`conversation_settings` 表已存在，`create_all` 不会 ALTER——追加幂等迁移 `ALTER TABLE conversation_settings ADD COLUMN IF NOT EXISTS permission_mode TEXT`（Postgres 原生支持，重复执行无害）。
3. **schemas.py**：`ConversationSummary` 加 `workspace_root: str | None` 与 `permission_mode: str | None`（列表/详情/创建响应统一带出）；新增 `PermissionModeSetRequest { mode: Literal["default","accept_edits","explore","dont_ask"] }`。
4. **conversations.py**：
   - `list/get/create` 组装 workspace_root / permission_mode（selectinload(Conversation.setting)）。
   - **工作区不可变**：`PUT /{id}/workspace` 已有设置时返回 **409**（"工作区已设定，不可更改；请新建对话"）；不再支持置 null 恢复默认（前端入口同步移除）。
   - 新增 `PUT /{id}/permission-mode`：校验会话归属 + Literal 合法性后 upsert，随时可改。
5. **chat.py**：读 setting 时同时取 permission_mode，**生效优先级：会话设置 > 请求参数 > "default"**（服务端权威，前端忘传也一致）；meta 记录实际生效值。

## 前端改动

6. **lib/api.ts**：`Conversation` 类型加 `workspace_root?/permission_mode?`；新增 `setPermissionMode(token, convId, mode)`；删除不再使用的 `getWorkspace`（数据改由会话详情带出）。
7. **store/ui.ts**：加 `conversationsVersion` 计数 + `bumpConversations()`——解决两个已知刷新缺口：ChatWorkspace 懒创建用 `replaceState` 不触发 Shell 重拉（新会话不出现在侧边栏）、工作区/权限变更后分组需刷新。懒创建/新建工作区会话后 bump。
8. **Shell.tsx（主战场）**：
   - 「开启新对话」旁新增**「新建工作区对话」**按钮（FolderAddOutlined）：流程 = 先 `pickWorkspace` 弹原生选框 → 用户取消则什么都不发生（零副作用）→ 选定后 `createConversation` + `setWorkspace` + `bumpConversations` + 跳转该会话。
   - 会话列表按 `workspace_root` 分两组渲染：「工作区」（带文件夹图标，`sidebar-collapsed` 折叠态隐藏组头）与「对话」；组头小标题样式与现有导航一致。
   - effect 依赖加 `conversationsVersion`，增删改会话后列表自动刷新。
   - 移动端：现有手写抽屉/遮罩结构不动，新按钮与分组自动继承滑入行为；按钮触控高度 ≥32px，折叠态图标化。
9. **ChatWorkspace.tsx**：
   - **删除**：Agent 工具 chip、工作区按钮、权限 Select、工作区展示条（含「恢复默认」）、`SHOW_AGENT_TOOLS`、`agentTools` state、`chooseWorkspace/clearWorkspace`、`getWorkspace` effect。
   - **数据驱动**：打开会话时从详情响应 `workspace_root/permission_mode` set 到 state（切换会话重置）；新对话两者为空。
   - **发送载荷**：`agent_tools: !!workspaceRoot`（有工作区即自动开启，不可关）、`permission_mode` 用会话记住的值。
   - **权限选择器新形态**：仅有工作区的会话显示；输入框工具栏内一枚 chip（SafetyOutlined + 当前模式短名，选中态与深度思考/联网搜索同 brand 样式），点击弹 AntD Dropdown 菜单四选一（含一句说明），选中即乐观更新 + `setPermissionMode` 存库。移动端天然适配（Dropdown 弹层，chip 宽度自适应）。
   - **头部工作区标识**：消息区头部标题旁加 `FolderOpenOutlined + 短路径`（`truncate` 截断 + title 提示全路径），让用户随时可见当前工作区（原输入框展示条已删）。

## 测试与文档

10. tests：`PermissionModeSetRequest` Literal 校验（非法值拒绝）；workspace 不可变与 permission-mode 的路由行为需 DB/HTTP 基建（项目现无），以手动验证为准并在计划内注明；既有 81 用例不回归。
11. ARCHITECTURE.md §10 更新：会话级权限模式持久化（优先级链）、工作区不可变语义、侧边栏分组与新建工作区会话流程；README 功能行同步。

## 移动端要点汇总

- 侧边栏新内容全部走现有抽屉机制（`md:` 断点切换、遮罩、路由自动收起），不新增断点；
- 权限选择器为 chip+Dropdown，无固定宽度依赖；
- 头部工作区标识 `truncate` 处理长路径；
- 折叠态侧栏遵守 `sidebar-collapsed:md:*` 既有约定（组头隐藏、按钮图标化）。
