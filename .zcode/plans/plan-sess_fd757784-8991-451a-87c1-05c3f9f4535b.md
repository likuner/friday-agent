## 计划:新建《记忆方案》文档

**新建文件:`MEMORY.md`**(仓库根目录,与 README.md / ISSUES.md / POC.md 同级);只写这一个文件,不改代码、不动 ISSUES.md。

### 文档结构(中文)

1. **TL;DR** — 一页速览:现状结论 + 方案总表(短期/长期各一行:存哪、何时写、何时读)
2. **现状与问题** — 短期记忆六大问题(跨用户串味、history 死参数、重启失忆、无 token 预算、并发中止连锁、开关切换丢上下文),长期记忆完全缺失;附当前存储位置表(进程内存 `state.context` / `messages` 表只存不读)
3. **总体架构** — ASCII 分层图:短期记忆(会话内)与长期记忆(跨会话三层)如何共同构成每轮模型上下文
4. **短期记忆方案** —
   - 显式回放:每轮从 `messages` 表按 token 预算取最近 K 轮;AgentScope 2.0.8 正确姿势(`AgentState`/`observe()` 回放,历史不得带 tool_call 块,`reply(None)` 续聊)
   - Token 预算分配图(system+工具定义固定 / 会话摘要 ~500 tok / 最近 K 轮弹性 / 本轮附件固定)
   - 滚动摘要:`conversations` 表加 `summary` + `summary_upto_message_id`,便宜模型异步压缩、避免每轮重算
   - 存储一览:全部复用业务库,不引入新组件
5. **长期记忆方案(三层)** —
   - L1 结构化画像 `user_profiles`(JSONB),每轮注入 system prompt
   - L2 事实条目 `user_memories`(内容+向量+置信度+来源消息 id),对话结束异步抽取、按当前问题向量 Top-K 召回
   - L3 历史检索:`messages` 向量化,支持"上次那个方案"式召回
   - 治理配套:写入把关、时效冲突(superseded_by/expires_at)、遗忘权(「我的记忆」页面)、注入标注、成本上限
6. **向量存储选型** — 推荐:业务库换 `pgvector/pgvector:pg16` 镜像并启用扩展(记忆与业务数据同库同事务);备选:复用 med-pgvector 实例(省事但语义混杂),含对比表
7. **实现路线对比** — 按 ISSUES.md 自研(推荐)vs 挂 AgentScope 自带长记忆中间件(Mem0/AgenticMemory,起步快但引入依赖、治理仍需自建)
8. **落地顺序** — 四步(短期回放(P0,随串味修复)→ 滚动摘要 → 用户画像 → 向量事实条目),每步附验证方式
9. **代码衔接点** — `agent.py stream()`/`chat.py history`/`models.py` 新表/前端「我的记忆」页面预留
