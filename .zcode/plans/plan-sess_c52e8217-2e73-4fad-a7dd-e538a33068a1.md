# 用 CrewAI 替换 AgentScope（多智能体实现）

## 目标与基线决策

在 feature/crewai 分支上，把 backend 的 AgentScope 2.0.10 运行时**完整替换**为 CrewAI（1.15.x），以多智能体形式（leader Friday + 检索员 + 执行员）实现全部现有功能。**前端、SSE 契约、DB 表结构（零加字段）、auth、mcp-server、shared 日志均零改动**。

- 数据库零改动依据：多智能体归属与协作过程（`multiAgent`、`toolCalls[].agent`、`agentTraces[]`）本来就存在 `messages.meta` JSONB 里（feature/multi-agent 分支未动 models.py）；历史回放只读 `role+content`；摘要/记忆/工作区/权限模式各有现成字段；「总是允许」规则仍留 ConfirmHub 进程内存。CrewAI 替换只换运行时（Agent/LLM/工具/事件来源），写库形状不变。

两个基线决策（已按推荐选定，可在审阅时推翻）：
1. **先 merge feature/multi-agent（f75a663）进 feature/crewai**：该分支仅领先 main 一个提交，带来现成的多智能体前端（协作过程面板、agent 归属、多 Agent 开关）、SSE `agent` 字段契约和团队提示词（LEADER_TEAM_PROMPT/RESEARCHER_PROMPT/EXECUTOR_PROMPT）。
2. **编排用自定义 TeamAssign 复刻 TeamPipeline 语义**：Friday 是带 `TeamAssign(member, prompt)` 自定义工具的 CrewAI Agent，工具内部驱动成员 CrewAI Agent 执行并返回结果。简单问题 leader 直答（无委派开销），复杂任务拆解委派、汇总作答——与现有 UX 完全一致。CrewAI 用作 Agent/LLM/工具/流式事件运行时，不用其 hierarchical process。

## 迁移面（现状盘点）

agentscope 耦合共 14 个文件（9 app + 5 测试/脚本）。保留不动：chat.py（SSE 序列化与 meta 持久化）、context.py、memory.py、summarizer.py、models/db/auth 全套、workspace_picker、conversations、files。

## 实施步骤

### 1. 基线合并
`git merge feature/multi-agent`（feature/crewai 当前 == main，可干净合并）。

### 2. 依赖与环境
- requirements.txt：删 `agentscope==2.0.10`，加 `crewai==1.15.*` + `crewai-tools[mcp]`；保留 `mcp`、httpx、sqlalchemy、otel 三件套（tracing.py 保留，默认关闭）。
- start.sh 不动（hash stamp 自动重建 .venv，python3.12 满足 crewai <3.14）。
- 安装时核对 crewai 依赖树与 fastapi 0.115.6 / pydantic 的版本兼容，必要时放宽 pin 并回归启动。

### 3. CrewAI 运行时层（新文件替换旧文件）
- **app/crew_llm.py**：每请求构造 `crewai.LLM`（litellm）指向 DeepSeek OpenAI 兼容端点（`model="deepseek/<model>"`、api_key=llm_api_key、base_url=llm_base_url、stream=True）；深度思考档经额外参数开 thinking（litellm extra_body，实测确认参数名）；带图请求换 llm_vision_model。
- **app/crew_tools.py**：内置工具移植——以 feature/langgraph 分支的 framework-free 实现（`git show feature/langgraph:backend/app/agent_tools.py`、`permissions.py`）为底，包成 CrewAI BaseTool（name/description/args_schema），工具名保持 Bash/Read/Write/Edit/Glob/Grep/TaskCreate/TaskGet/TaskList/TaskUpdate（前端 chip 与提示词不变）；任务工具用每请求内存 store。
- **app/crew_permissions.py**：权限引擎——模式（default/accept_edits/explore/dont_ask）、敏感路径 deny（.env/.git/.ssh/…+ backend 目录枚举）、workspace 外写拒绝、Bash allow-prefix、会话级「总是允许」重放、MCP readOnlyHint 自动放行。语义对齐现有 test_agent_tools 断言。**ASK 语义从 park/resume 改为工具内阻塞等待**：gate 判 ASK → ConfirmHub.register(PendingAsk) → 经事件队列推 `permission_ask` SSE → `threading.Event.wait(120s)`（跨线程安全）→ 批准执行 / 拒绝、超时返回「用户已拒绝」工具结果，模型换路完成。
- **app/crew_mcps.py**：`crewai_tools.MCPServerAdapter`（streamable-http + Bearer header + timeout 90s）拉工具，白名单过滤（medical_rag_search 恒挂、web_search 按开关），包权限 gate 后交给成员；保持 `mcp__common_tools__web_search` 命名（或核对 adapter 实际命名并同步 WEB_SEARCH_PROMPT）；probe 日志对齐。
- **app/crew_skills.py**：frontmatter 解析 skills/*/SKILL.md → `<agent-skills>` 清单注入 system prompt + 只读 `Skill` 元工具（输入技能名返回全文），复刻渐进披露。
- **app/crew_agents.py**（替代 agent_factory.py）：
  - 成员：检索员（MCP 工具+Skill）、执行员（内置工具+权限 gate），模型用基础档 llm_model；
  - leader Friday：Agent + TeamAssign 工具（member 取值即成员名，工具说明用 RESEARCHER_DESC/EXECUTOR_DESC）；**系统提示词**优先找 CrewAI 官方整体替换途径（system_prompt/prompt_template 类参数），否则 role/goal/backstory 承载 SYSTEM_PROMPT+记忆块+WEB_SEARCH_PROMPT+工具块；**当前北京时间**手动注入一行（替代 AgentScope InjectionConfig）；
  - **历史注入**：滚动摘要+记忆块进 leader system prompt，replay 窗口拼进 Task description（成员每轮全新，同现状）；
  - TeamAssign 实现：为成员建 Task → 独立线程跑成员 → 结果字符串作为工具结果回流；成员的 token/工具事件经事件总线带 agent 归属转发（首版串行委派，同轮多委派顺序执行——结构留并行口）；
  - 单 Agent 路径（multi_agent 关/带图/无成员）：同一个 CrewAI Agent 挂全部工具，一个 Crew+Task；
  - 带图请求：litellm 图片 content block 注入方式实测（Task/Agent 多模态参数），失败兜底为纯文本降级提示。

### 4. 流式与编排层
- **app/crew_events.py**（替代 agent_events.py）：`crewai.events` BaseEventListener 消费 LLMStreamChunkEvent（token 增量）与工具使用事件（chip）；agent key → "Friday"/检索员/执行员 映射；产出与现在**逐字段相同**的 SSE dict（text/thinking/tool_call 带 agent，tool_query 键优先级加 member，chip 去重、40 字截断）。thinking（DeepSeek reasoning_content）经 litellm 是否单独成增量需实测，不行则降级不发（前端兼容）。
- **app/agent.py** AgentService.stream() 改造：构建 crew → `asyncio.to_thread(crew.kickoff)` + `asyncio.Queue` 桥接（listener 在工作线程用 `call_soon_threadsafe` 入队）→ 事件循环转发 SSE；权限等待在工具内（见上）；abort：CancelledError → 置 stop 标志（工具入口检查）+ 停止消费，chat.py 部分保存逻辑不变；demo 降级保留（文案改提 CrewAI）。
- **app/crew_logging.py**（替代 agent_logging.py）：事件监听器记节点日志（模型调用/token/工具耗时），字段对齐现有日志格式。
- **confirm.py**：仅去掉 agentscope PermissionRule import，改用 crew_permissions 自有规则类型，其余不动。

## 主要风险与对策
1. CrewAI 无原生取消：stop 标志+工具入口检查+队列关闭兜底。
2. 权限 ASK 改工具内阻塞：worker 线程用 threading.Event，语义等效（超时自动拒、流不悬挂）。
3. CrewAI 系统提示词模板注入的框架额外指令：优先整体替换参数，兜底 backstory 承载。
4. thinking 流/多模态注入/并行委派三处依赖实测，均有降级路径且不破坏 SSE 契约与 DB 形状。
5. crewai 依赖树与现有 pin 冲突：安装时解决并回归。
