# mcp-server：通用公共工具 MCP 服务（独立静态 Token 鉴权）

## 目标与定位

在 `mcp-server/` 新建**独立子项目**（自己的 venv / 依赖 / .env / README），基于 FastMCP 实现一个**无状态**的通用 MCP 服务。首个工具为 `web_search`（调用智谱 GLM 联网检索，移植自 `backend/app/websearch.py`）。服务不绑定任何单一工具，后续公共工具只需在 `app/tools/` 下新增模块文件即可自动注册。

**消费方**：本地客户端（stdio 子进程，不受鉴权影响）与 agent Python 后端（同机 http）；考虑未来可能部署外网，http 传输启用独立静态 Bearer Token 鉴权。

## 鉴权设计（独立静态 Token）

- 配置：`MCP_AUTH_TOKEN` 环境变量，**支持逗号分隔多个值**（轮换时新旧并存实现零停机切换）；为空则不启用鉴权（本地开发）
- 实现：`app/auth.py` 的 `build_auth()` 用 FastMCP 的 `StaticTokenVerifier`（实现时按所装版本核对 import 路径与签名，必要时退化为 ~10 行自定义 `TokenVerifier` 子类做等价校验），传给 `FastMCP(auth=...)`
- 仅 http/sse 传输受鉴权约束（FastMCP 行为），stdio 不受影响
- 消费方式：`Authorization: Bearer <token>`；fastmcp Client 用 `auth=BearerAuth(token)` 或 `auth="<token>"`
- 与 backend 完全解耦：token 专属本服务，泄漏只影响本服务，改 env 重启即完成轮换（无状态、无下游依赖）
- README 写明：外网部署检查清单（强随机 token、`MCP_HOST=0.0.0.0`、前置 HTTPS 反代）、token 轮换步骤（新旧并存→切换→删除）、未来面向用户级消费方时升级 JWKS/IdP 的路径（届时只换 auth 模块，工具代码零改动）

## 技术选型

- **`fastmcp`**（独立包）：比官方 SDK 内置版更适合做可扩展的通用服务（中间件、多传输、鉴权体系等）
- **httpx**：异步调 GLM API（与 backend 一致）
- **pydantic-settings**：配置管理（与 backend `config.py` 同款模式）
- 传输层**可配置、默认 stdio**：本地客户端用 stdio；`MCP_TRANSPORT=http` 时以 streamable-http 监听（默认 127.0.0.1，外网部署时改 MCP_HOST）

## 关键设计

### 1. 无状态
- 工具均为纯函数：每次调用独立创建 `httpx.AsyncClient`，无会话、无存储、无跨调用可变全局；settings 启动时加载后只读
- 鉴权只做 token 比对，不落地任何会话状态——token 可随时替换（改 env 重启即生效）

### 2. 可扩展的工具注册（约定优于配置）
- `server.py` 只创建 FastMCP 实例（含 auth）→ 工具模块 `from app.server import mcp` 后用 `@mcp.tool` 装饰 → `tools/__init__.py` 用 pkgutil 自动 import 全部子模块
- **新增公共工具 = 在 `app/tools/` 加一个文件**，无需改任何既有代码（README 写明此约定）

### 3. web_search 工具（移植自 backend/app/websearch.py）
- 完整保留：`_glm_web_search`（GLM chat/completions + `tools=[{type:"web_search", search_engine, search_result, count}]`，timeout=60）、双路结果解析（顶层 `web_search` 字段优先，回退 `tool_calls[].web_search.search_result`）、`_format_results`（摘要 + 编号来源列表、`<think>` 清洗、800 字符截断）、异常兜底返回可读文本而非抛出
- 适配差异：
  - 参数用 `Annotated[..., Field(description=...)]` 提供 MCP schema 描述；docstring 作为工具描述（保留「何时调用」引导）
  - 调用时检查 `zhipu_api_key`，未配置返回明确提示（替代 backend 的前端降级逻辑）

### 4. stdio 协议安全
- stdio 下 stdout 是 JSON-RPC 通道，日志一律走 stderr：`logging.basicConfig(stream=sys.stderr)`

## 实施步骤

1. 创建目录与文件骨架（README 最后写）
2. `app/config.py`：Settings（zhipu_api_key / glm_base_url / glm_model / glm_search_engine / mcp_auth_tokens / mcp_transport / mcp_host / mcp_port），.env 绝对路径锚定
3. `app/auth.py` + `app/server.py`：静态 token 鉴权构建与 FastMCP 实例
4. `app/tools/web_search.py` + `tools/__init__.py` 自动注册
5. `app/main.py` + `__main__.py`：stderr 日志、stdio/http 双模式运行
6. `python3 -m venv .venv && pip install -r requirements.txt`；核对所装 fastmcp 版本 API（StaticTokenVerifier import 路径与签名、`transport="http"` 写法、Client 鉴权用法）
7. 从 `backend/.env` 复制 ZHIPU_API_KEY 到 `mcp-server/.env`；生成一个测试用 MCP_AUTH_TOKEN
8. 冒烟测试：stdio 内存直连 list_tools + 实调 web_search（真实 GLM 检索返回带来源结果）+ 无 key 场景可读提示；http 模式起服务后：无 token / 错 token → 401，正确 token → 调用成功
9. 编写 README（启动方式、鉴权与轮换、backend http 接入与 ZCode stdio 接入示例、新增工具指南、外网部署检查清单）
