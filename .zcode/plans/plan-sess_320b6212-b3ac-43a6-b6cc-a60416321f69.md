# Agent 执行段日志迁移为中间件形式

## 目标
把 `backend/app/agent.py` 中属于 Agent 执行段的 `节点[...]` 日志迁移到自定义 AgentScope 中间件,`stream()` 只保留「事件 → SSE 翻译」职责。已确认(读 agentscope 2.0.8 源码):`on_reasoning`/`on_reply` 钩子里能看到与 `reply_stream` 相同的事件流(`ModelCallStartEvent` 自带 model_name,`ModelCallEndEvent` 自带 input/output_tokens);`on_acting` 的 `input_kwargs["tool_call"]` 是解析好的 `ToolCallBlock`(`.name/.id/.input`,input 为原始 JSON 字符串),结束时产出 `ToolResponse`(`.state` 为 SUCCESS/ERROR/DENIED/INTERRUPTED)。

## 1. 新建 `backend/app/agent_logging.py`
`AgentLoggingMiddleware(MiddlewareBase)`,沿用 `logger = logging.getLogger("friday.agent")`(日志名不变,grep/过滤习惯不受影响)。三个钩子:

- **on_reply**:不记开始(`stream()` 的 `节点[Agent调用]` 已覆盖 replay/摘要/模型/开关等服务上下文);流结束记 INFO `节点[Agent返回] 模型流结束 耗时=%.2fs`(perf_counter 计时,try/finally 兜底)。
- **on_reasoning**(实例级轮次计数,每轮 Agent 独立构建故实例状态安全):
  - `MODEL_CALL_START` → INFO `节点[模型调用] round=%s model=%s session=%s`
  - `MODEL_CALL_END` → INFO `节点[模型返回] round=%s input_tokens=%s output_tokens=%s finished=%s`(token 用量为本次新增能力)
  - `TEXT_BLOCK_DELTA` / `THINKING_BLOCK_DELTA` → 逐 token DEBUG 日志**保留代码但注释掉**(按你的选择,与现状一致)
- **on_acting**:
  - 开始 INFO `节点[工具调用] name=%s call_id=%s args=%s`(input 截断 200 字符,原生 JSON 字符串直接用,不再手工拼 delta)
  - 结束 INFO `节点[工具结果] name=%s call_id=%s state=%s 耗时=%.2fs`;`state==ERROR` 升 WARNING 并附内容预览
  - `next_handler` 抛异常时 `logger.exception` 后原样 re-raise
- 防御模式参照 TracingMiddleware:`input_kwargs.get(...)` + isinstance 守卫;事件透传用普通 `async for ... yield`。
