# 会话级记忆：上下文管理 + 压缩摘要 + 落库（实现计划 v2）

## 0. 一句话方案

把"记忆"从进程内存搬到 PostgreSQL：**每轮用「滚动摘要 + 预算内最近若干轮全文」显式装配模型上下文，被预算挤出的早期历史异步压缩成摘要写回库**。Agent 彻底无状态（每轮新建），跨用户串味、重启失忆、中止连锁、切开关丢上下文四个 P0 问题随之消失。

范围：MEMORY.md 落地顺序的步骤 1+2（短期记忆全套），不含长期记忆；迁移用启动幂等 ALTER（已确认）。

## 1. 用户要求的三项能力分别怎么落

| 要求 | 机制 | 代码落点 |
| --- | --- | --- |
| 会话级记忆 | 每轮从 `messages` 表回放该会话历史（显式、无状态） | `agent.py`（observe 回放）+ `chat.py`（取数） |
| 压缩 | 两级：① token 预算截断回放窗口（硬上限）② 溢出段滚动摘要（软压缩） | `context.py`（窗口切分）+ `summarizer.py`（摘要） |
| 摘要 | GLM `glm-4-flash`（已有密钥、免费档）滚动合并旧摘要+溢出段，约 500 token | `summarizer.py` |
| 落库 | 消息全文已在 `messages` 表；摘要新增 `conversations.summary` + 进度游标两列 | `models.py` + `db.py` |

## 2. 一轮对话的完整时序（核心逻辑）

```
用户发消息
 1. 校验会话归属，用户消息落库（现状不变）
 2. 读 conversations.summary / summary_upto_message_id + 该会话全部消息
 3. context.py 按预算切分（从最新向前累加 token，塞满即停）：
      ├─ 溢出段 overflow ：早于窗口、晚于摘要游标 → 待压缩
      ├─ 回放窗口 replay ：预算内最近若干轮（清洗后纯文本）
      └─ 摘要 summary   ：直接注入
 4. overflow ≥ 阈值 → asyncio.create_task(update_rolling_summary(...))
    （后台独立 session，不阻塞、不依赖本轮回复成败）
 5. 每轮新建 Agent：
      state = AgentState(session_id=会话id, summary="【此前对话摘要】"+summary)
      await agent.observe(replay)          # 回放历史（纯文本 user/assistant）
      reply_stream(本轮消息+图片)           # 图片只随本轮发
 6. 回复流式返回、assistant 消息落库（现状不变）
```

后台摘要任务：加锁 → 重算窗口 → 取 overflow → GLM 压缩（旧摘要+溢出段 → 新摘要）→ 写回 `summary` 与 `summary_upto_message_id = overflow 末条 id` → commit。**游标保证幂等**：每轮重算，漏压/失败下轮自动补。

## 3. 存储设计

```sql
ALTER TABLE conversations ADD COLUMN IF NOT EXISTS summary TEXT;              -- 滚动摘要，NULL=未生成
ALTER TABLE conversations ADD COLUMN IF NOT EXISTS summary_upto_message_id UUID; -- 摘要已覆盖到的消息 id（进度游标）
```

- 放启动流程 `create_all` 之后执行（`db.py`），幂等、零新依赖；
- 摘要存 conversations 表内（与会话一对一，主查询免 join），不新建表；
- 回放上下文本身不落盘：每轮从 messages+summary 现算，用完即弃。

## 4. 分阶段实现（每阶段独立可验收）

### 阶段 A：存储层
**改动**：`models.py`（Conversation 加 `summary: str | None`、`summary_upto_message_id: UUID | None`）、`db.py`（启动幂等 ALTER）。
**验收**：启动无报错，`\d conversations` 出现两列；旧数据不受影响。

### 阶段 B：上下文装配层 `context.py`（新建，纯函数无 IO）
**内容**：
- `estimate_tokens(text)`：字符近似——中文字数÷1.6 + 非中文÷4，不引 tokenizer；
- `build_context_window(messages, summary_upto_id, budget) -> (replay, overflow)`：
  - 早于等于游标的消息跳过（已压缩），其余从新到旧累加 token 塞满预算即停；
  - 单条超剩余预算则整条不塞（不切半条），作为窗口边界；
  - 清洗：`meta.attachments` → 内容前置「[图片]」占位；空 content（中止空回复）跳过；toolCalls/thinking 只在 meta、天然不回放。

**验收**：`pytest backend/tests/test_context.py` 全绿（估算、截断、游标排除、占位、三段拼回等于全集）。

### 阶段 C：Agent 无状态化（P0 修复本体）
**改动**：
- `agent.py`：删 `_agents` 实例缓存；`stream()` 改签名为 `(conversation_id, replay, summary, content, attachments, deep_thinking, web_search)`，每轮 `AgentState(session_id, summary) + Agent(...)` → `observe(replay)` → `reply_stream(本轮消息)`；credential 缓存与演示模式分支保留；
- `chat.py`：删死参数 history 拼接，改调 `build_context_window`，把 replay/summary 传给 stream；现有 sent/done 事件、中止落库、标题改写逻辑不动。

**验收**：①两会话并发「紫色河马」不串味；②重启后端后会话仍连贯；③中止只影响本会话；④中途切深度思考/联网开关上下文保留。

### 阶段 D：摘要压缩管线 `summarizer.py`（新建）
**内容**：
- `update_rolling_summary(conversation_id)`：独立 `SessionLocal`；模块级 `dict[UUID, asyncio.Lock]` 防同会话并发；重跑窗口得 overflow，为空直接返回；
- GLM 非流式 `chat/completions`（复用 `zhipu_api_key`/`glm_base_url`，参考 `websearch.py` 调用方式）：输入=旧摘要+溢出段全文，提示词要求合并为中文摘要、保留用户偏好/已确认事实/决策结论/未决问题、≤500 token；
- 写回两列并 commit；日志用现有「节点[摘要]」风格记 token 收益；
- 触发点在 `chat.py` 构建窗口后（流式开始前）`create_task`，不依赖回复完成。

**验收**：50+ 轮长会话后 `conversations.summary` 非空、早期事实仍可答、日志出现压缩记录、回放 token 有上限。

### 阶段 E：配置与收尾
**改动**：`config.py` 加 `context_token_budget=16000`、`summary_max_tokens=500`、`summary_min_overflow_tokens=2000`（溢出攒够才压，避免频繁小压缩）；`requirements-dev.txt`（pytest）。

## 5. 边界与失败策略

| 场景 | 行为 |
| --- | --- |
| 压缩任务失败/进程重启 | 只记日志；下轮发现 overflow 仍在自动重试（自愈） |
| 未配置 zhipu key | 摘要停用（warning 一次），窗口照常截断，退化为丢早期上下文 |
| 同会话并发请求 | per-conversation 锁 + 游标幂等，重复触发无害 |
| 用户中止生成 | 部分回复已落库照常参与下轮回放；本轮摘要触发缺失由下轮自愈 |
| 新会话 / 预算内短会话 | summary 为空、overflow 为空，全量回放，零额外开销 |
| 单条消息超预算 | 整条不塞半条，作为窗口边界（当前轮消息不受影响，走 reply_stream 输入） |

## 6. 关键设计决策

- **不用 AgentScope 内置 `ContextConfig` 压缩**：它作用于进程内 context，与"无状态回放"架构冲突，且用主模型压缩更贵（MEMORY.md §七已论证自研）；
- **摘要注入用 `AgentState.summary`**：框架自动 prepend 到模型上下文（已核实 `_agent.py:581`），注入侧零代码，构造时加「此前对话摘要」标注前缀；
- **回放姿势用 `observe + reply_stream(本轮消息)`**：AgentScope 已核实支持，且图片附件只随本轮消息发送；
- **摘要触发在流式开始前而非回复后**：单一触发点，不依赖回复成败/中止路径，正确性由游标幂等兜底。
