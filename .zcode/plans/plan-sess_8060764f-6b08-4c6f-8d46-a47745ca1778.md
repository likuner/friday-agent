# 用户记忆改为「每用户一条」聚合存储

## 0. 设计

`user_memories` 表每用户只留一行，`content` 存全部事实的聚合文本（`- 姓名：李坤\n- 偏好：喜欢游泳\n...`）。每次抽取 = GLM 把「旧记忆全文 + 新消息段」合并重写为新记忆全文——与 `summarizer.py` 完全同构的已验证模式。

护栏两道（针对合并模型的失误模式）：
- **行级精确去重**：写回前按行 exact 去重（合并模型复读同一行时拦截——你昨天遇到的重复问题在这里的等价兜底）；
- **长度上限**：合并提示词限定新记忆 ≤ `memory_max_tokens`（500 tok ≈ 80 行以内），配合每次合并"携带旧全文"，体积有界。

## 1. 表结构（models.py + 一次性数据迁移）

```
user_memories: id UUID PK | user_id UNIQUE FK(users.id, CASCADE) | content Text | updated_at
```

- 删去 confidence / superseded_by / source_conversation_id；
- 存量数据保留：一次性脚本把现有 6 条活跃条目按用户聚合为一行（`- ` 前缀逐行拼接）→ DROP 旧表 → `create_all` 重建新结构 → 回填；
- `conversations.memory_extracted_upto` 游标列与触发机制不变。

## 2. memory.py 重构（代码量约减半）

- **读取** `load_memory_block(session, user_id)`：查唯一行 → content 即注入块（套现有标注头）。无条数/token 截断分支；
- **抽取** `extract_user_memory(conversation_id, user_id)`：锁/游标/自愈模式不变；GLM 合并提示词（旧记忆 + 新消息段 → 新记忆全文；分行 `- ` 格式；**合并而非追加**：去重、新信息覆盖旧信息如"换城市"、丢弃不再成立的条目、≤500 tok）——输出**纯文本**，删掉 `parse_extraction`（JSON 解析）与 `dedupe_facts`；
- **写回前**：按行 strip + exact 去重（`_dedupe_lines` 纯函数，可单测）；
- 删除 `_enforce_cap` 封顶清理与置信度过滤（体积由合并上限控制，取舍由合并模型控制）。

## 3. 接线与配置

- `chat.py` / `agent.py` **零改动**（`load_memory_block` 签名与 `memory_block` 参数不变）；
- `config.py`：删 `memory_extract_confidence_threshold` / `memory_inject_max_entries` / `memory_inject_max_tokens` / `memory_max_active_entries`，保留 `memory_enabled`、`memory_extract_min_messages`，新增 `memory_max_tokens = 500`（合并输出上限）。

## 4. 测试与验证

- 单测：`_dedupe_lines`（批内/空白规范化）、`load_memory_block` 组装；删除 parse/dedupe_facts 相关用例；
- 存量迁移后查库确认每用户恰一行、6 条事实都在；
- 真实链路回归（与今日同法）：会话 A 说"记住我在杭州工作、喜欢紫色" → 抽取合并落库（一行）→ 新会话问城市答"杭州" → 再说"换到上海" → 合并后记忆里城市更新为上海且旧值消失 → 新会话答"上海"。

## 6. 明确接受的代价

- 合并模型偶发丢改个别条目（漂移）：靠"携带旧全文 + 行级去重"缓解，与滚动摘要同级风险；
- 将来要按条管理/向量召回时需把聚合文本拆回条目（一次 LLM 调用），注入管线不变。
